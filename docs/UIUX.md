## 0. 设计决策摘要

### 0.1 寄存器判定：Product

本产品是**流程型工具**（上传 → 抽帧 → 多引擎反搜 → 汇总溯源），不是营销站或作品集。判定为 Product 寄存器，遵循以下策略：

| 维度 | 策略 |
|---|---|
| 色彩 | 克制。中性色 88% + 单一强调色 ≤8% + 语义色 ≤4%（引擎状态/降级） |
| 排版 | 全 Sans-Serif。**禁止衬线体**。数值/域名/时间戳用等宽 |
| 动效 | 功能性动效为主，150ms 收敛。**禁止装饰性动画** |
| 图片 | 不使用照片/插画。视觉元素 = 帧缩略图 + 图标 + 数据条 |

### 0.2 对标品牌：**Linear（克制密度）为主 + Figma（数值精度）为辅**

**为什么选 Linear 而不是 Figma：**

1. **主体形态不同。** Figma 是"画布为中心、面板环绕"的创作工具，视觉重心在一个大画布上；我们是**列表/网格即主体**的数据流程工具（任务队列、帧网格、结果列表），Linear 的"列表即主体、边框极轻、选中态明确、密度可控"直接对应。
2. **密度量级不同。** Figma 的 11px 字号 + 20px 行高 + 密集图标按钮对我们**过头了**——我们的结果行含 96×54 缩略图，需要呼吸空间；Linear 的 28–32px 行高 + 1px 分隔线更合适。
3. **结果项语义不同。** Figma 面板是"持续操作的对象"，我们的结果行是"扫读后点开的条目"——扫读效率优先于操作密度。

**从 Figma 借鉴的三点（明确列出，避免含糊）：**

- **数值用等宽字体并右对齐**：相似度百分比、帧序号、耗时全部 `font-variant-numeric: tabular-nums`，列内小数点对齐。
- **状态用「颜色 + 图标」双重编码**：引擎状态不只靠颜色圆点区分（色盲不可读），必须同时有图标形状差异。
- **面板可折叠、宽度可拖**：帧网格与结果面板之间的分割线可拖拽，记住用户偏好。

**额外参考 GitHub Primer 的蓝色体系**——本项目是本地服务，面向会用 ffmpeg / CLI 的重度用户，Primer 的工程感与该人群的心智模型一致（这也是主色选型的来源，见 §2.1）。

### 0.3 三轴刻度标定

| 参数 | 值 | 理由 |
|---|---|---|
| **DESIGN_VARIANCE** | **3** | 工具型产品，用户来扫数据不要惊喜。但**首屏不用居中 Hero**：工作台用左重非对称（上传区占左 60%，任务列表占右 40%），符合 Variance >2 的强制偏移要求。 |
| **MOTION_INTENSITY** | **3** | 批量任务一次跑几十分钟，多余动画是干扰。仅保留：hover/active 150ms、进度条持续微光、引擎轮询脉冲点、Compare 视图 300ms 切换。**其余一律静态。** |
| **VISUAL_DENSITY** | **7** | 任务队列 + 帧网格 + 结果列表同屏，必须接近驾驶舱。用 `border-top` / `divide-y` 的 1px 线分组，**不给每条数据套卡片盒**。表格紧凑行高 28px。 |

### 0.4 行业调研结论（TinEye / Yandex Images / Google Lens / Bing Visual Search）

调研提炼出的 10 条行业惯例，本设计逐条落地：

| # | 行业惯例 | 来源 | 本产品落地方式 |
|---|---|---|---|
| 1 | **拖拽即启动**，松手就开始处理，无二次确认按钮 | TinEye / Yandex | 上传区 drop 后立即创建任务并入队，不弹确认框 |
| 2 | **上传方式三合一**：拖拽 + 点击选择 + 粘贴/URL | TinEye | 上传区底部一行三个入口，等宽排布 |
| 3 | **查询图锚点固定可见**：结果页始终显示原图供比对 | Google Lens（左）、Yandex（左 Smart Camera） | 任务详情页左上固定"当前帧"锚点，切换帧时锚点原地替换 |
| 4 | **结果三段式**：视觉相似网格 + 来源站点列表 + 排序/筛选工具条 | Google Lens / Yandex（Search / Similar / Sites） | 详情页三栏：帧网格（左）／结果列表（中）／来源详情（右） |
| 5 | **结果项元数据三件套**：缩略图 + 来源域名 + 页面标题 | TinEye / Yandex 共识 | 结果行固定四列：缩略图 / 标题+域名 / 双数值 / 操作 |
| 6 | **排序控件集中顶部**，且提供 4–5 种语义化排序 | TinEye（5 种） | 工具条排序下拉 5 项（见 §13.4） |
| 7 | **对比视图（Compare）是反向图搜的核心差异化交互** | TinEye（Your image ↔ Image match 并排切换） | 帧溯源详情提供「并排对比 / 叠加切换」两模式（见 §13.5） |
| 8 | **相似度表达有两种流派**：TinEye 只给排序位置不给数值；Yandex 给"像素重合率数值" | TinEye / Yandex | 本产品**同时给两个**（排序百分位 + 哈希相似度），正好覆盖两派语义，见 §13 |
| 9 | **键盘方向键在结果网格移动焦点，回车打开源页** | Yandex | 帧网格与结果列表均支持方向键导航 + Enter 打开 |
| 10 | **"无结果"的语义必须准确**：TinEye 明确说明"没有结果 ≠ 原创证明"，只代表不在索引里 | TinEye 官方说明 | 空状态文案严格按此语义撰写，**禁止写"未找到来源"这类结论性表述**（见 §11.6） |

**行业空白 = 本产品的机会点：** 这四个工具**没有一个做多引擎聚合**，也**没有一个显式暴露引擎健康度**（要么成功要么整页报错）。这两点正是我们的差异化，UI 上对应：
- **跨引擎交叉验证徽章**（§13.3）—— 多引擎聚合才有
- **引擎状态 + 降级提示条体系**（§12）—— 工具型产品的诚实暴露

### 0.5 图标方案锁定

**全项目唯一一套：内联 SVG sprite。**

- 实现：页面内嵌 `<svg style="display:none">` 定义 `<symbol id="rvs-icon-{name}" viewBox="0 0 24 24">`，使用处 `<svg class="icon" width="20" height="20" aria-hidden="true"><use href="#rvs-icon-{name}"/></svg>`
- 统一属性：`fill="none" stroke="currentColor" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"`
- 尺寸档位：**16px**（行内）/ **20px**（按钮内）/ **24px**（独立图标）/ **12px**（缩略图角标）
- 风格基线：几何简洁、端点圆角、无填充——与 Lucide 规范一致；但**自建 sprite，零外部依赖**（本地服务必须离线可用）
- **禁止混用第二套图标库**
- **禁止 emoji 充当功能图标**（完整图标清单与 path 见 §14）

## 1. Visual Theme & Atmosphere

**关键词（5 个）：** 冷静、精确、可核查、工程感、克制

**氛围描述：** 深色为底，1px 细线分区，数据以等宽字体对齐成列；强调色只在"当前选中"和"主操作"两处出现。整体接近一台校准过的测量仪器——用户在这里做溯源取证，界面不能替他下结论，只能把证据摆清楚、把不确定性标出来。

**对标品牌：** Linear（密度与克制）／ GitHub Primer（配色与工程感）／ Figma（数值精度与面板行为）

**首屏禁令落地：** 工作台首屏**不出现**居中大标题 + 副标题 + CTA + 抽象图形。首屏左侧是真实可用的拖拽上传区，右侧是真实的历史任务列表（有数据即渲染，无数据走空状态）。页面标题 `溯源工作台` 为 28px 左对齐，位于顶部工具条下方，不是 Hero。

## 2. Color Palette & Roles

完整变量见 `docs/design-tokens.css`。本节只说明**角色与用法约束**。

### 2.1 A1 — 强调色选型

| | 深色 | 浅色 |
|---|---|---|
| `--accent` | `#2F81F7` | `#0969DA` |
| `--accent-hover` | `#4C92F8` | `#0A58CA` |
| `--accent-active` | `#1F6FEB` | `#0550AE` |

**选型理由（4 条）：**
1. **语义契合**：溯源/取证 = 冷静、可靠、技术性；蓝是工具型产品的信任色。
2. **避开 P1 首罪**：明确不是 Tailwind 默认 Indigo `#6366F1`。`#2F81F7` 色相 213°、饱和度高，与 Indigo（色相 239°）肉眼可分。
3. **与语义色零混淆**：引擎状态点会同时显示绿（成功）/ 琥珀（限频与超时）/ 红（失败），强调色必须远离这三个色相。蓝是唯一安全解——这是**不选 Teal 的决定性理由**（Teal 与 success 绿太近，会造成状态误读）。
4. **人群匹配**：面向会用 ffmpeg 的重度用户，GitHub Primer 蓝是该人群最熟悉的工程色。

**对比度核验（深色 `#0D1117` 底 / 浅色 `#FFFFFF` 底）：**

| Token | 深色比值 | 浅色比值 | 达标 |
|---|---|---|---|
| `--fg` | 14.9:1 | 15.3:1 | AAA |
| `--fg-2` | 9.5:1 | 9.1:1 | AAA |
| `--muted` | 6.2:1 | 7.0:1 | AA |
| `--meta` | 4.8:1 | 4.6:1 | AA（最低可用，仅用于非关键元数据） |
| `--accent` | 5.0:1 | 4.6:1 | AA |
| `--success` | 7.6:1 | 4.6:1 | AA |
| `--warn` | 8.3:1 | 5.7:1 | AA |
| `--danger` | 5.6:1 | 5.0:1 | AA |

### 2.2 A2 — 语义色角色

| Token | 深色 / 浅色 | 专用于 |
|---|---|---|
| `--success` | `#3FB950` / `#1A7F37` | 引擎成功；哈希相似度 ≥90% |
| `--warn` | `#D29922` / `#9A6700` | **降级主色**：引擎超时、已重试、结果偏少 |
| `--danger` | `#F85149` / `#CF222E` | 引擎彻底失败、任务失败、破坏性操作 |

### 2.3 B-slot / C-extension — 项目专属色

- **引擎状态色**（C）：`--engine-idle` / `--engine-running` / `--engine-ok` / `--engine-throttled` / `--engine-timeout` / `--engine-failed` / `--engine-disabled`
- **评分条色**（C）：`--score-fill-high`（≥90% success）/ `--score-fill-mid`（70–89% 中性 fg-2）/ `--score-fill-low`（<70% 中性 meta）；`--rank-fill` **恒用中性色**
- **降级提示条色**（C）：`--degraded-{info,warn,danger}-{bg,border,fg}`

### 2.4 强调色用量规则

**每屏 ≤2 处可见的 `--accent`。** 本产品的 2 个额度固定分配给：

1. 主操作按钮（工作台：`开始溯源`；详情页：`重新查询此帧`）
2. 当前选中行的左边框或选中底（帧网格选中帧 / 结果列表选中行）

**其余一律不得用 accent。** 特别是：
- 相似度高**不**用 accent，用 `--success`（否则与选中态混淆）
- 引擎"查询中"**不**用 accent 实心填充，用状态点（`--engine-running`）+ 边框脉冲
- 链接不用 accent，用 `--fg` + 下划线（hover 时才转 accent）

## 3. Typography

### 3.1 字体栈

```
--font-display: "Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, -apple-system, sans-serif;
--font-body:    "Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, -apple-system, sans-serif;
--font-mono:    "JetBrains Mono", "SFMono-Regular", "Cascadia Mono", "Consolas", "Noto Sans Mono CJK SC", monospace;
```

**选型说明（诚实交代，不做虚假声明）：**
- Inter 作为**正文/UI 字体**使用（反射拒绝列表中 Inter 允许作为正文，仅禁止声称其为"高级展示字体"）。本项目是工具型产品，**本来就不需要展示字体**——标题用 Inter 590 字重 + 负字距即可，这是符合产品性质的诚实选择，不是偷懒。
- 中文用 Noto Sans SC，与 Inter 的 x-height 接近，混排不跳。
- 等宽用 JetBrains Mono，专供**数值、域名、时间戳、哈希、ffmpeg 命令、日志**。
- **离线约束**：本产品是本地服务，**禁止依赖 Google Fonts CDN**。前端须将字体文件本地托管（`public/fonts/`），`@font-face` 声明，加载失败时回退到 `PingFang SC / Microsoft YaHei / system-ui`，**不允许出现字体空白期（FOIT）**：`font-display: swap`。

### 3.2 字号阶梯（8 级，基准 13px）

| Token | 值 | 用途 |
|---|---|---|
| `--text-xs` | 11px | 缩略图角标数字、帧序号 |
| `--text-sm` | 12px | 表头、辅助说明、Badge 文字 |
| `--text-base` | **13px** | **UI 基准**：表格行、列表项、按钮、菜单 |
| `--text-md` | 14px | 正文段落、结果标题 |
| `--text-lg` | 16px | 区块小标题（面板标题） |
| `--text-xl` | 18px | 页面标题 |
| `--text-2xl` | 22px | 面板主标题 |
| `--text-3xl` | 28px | 唯一大标题（工作台首屏，全站仅此一处） |

### 3.3 字重（3 级）与字距

| 级别 | 值 | 用途 |
|---|---|---|
| Read | 400 | 正文、描述、表格内容 |
| Emphasize | 510 | 表头、小标题、按钮文字、域名 |
| Announce | 590 | 页面标题、关键数值（相似度百分比、命中总数） |

| 场景 | 字距 |
|---|---|
| ≥22px 标题 | `-0.02em` |
| 16–18px 标题 | `-0.01em` |
| 正文 | `0` |
| 全大写拉丁标签 | `0.08em` |
| 等宽数值 | `0` |

### 3.4 中文排版细则

- 正文行高 **1.6**（中文需要），表格行行高 **1.35**
- 中英文/数字之间**不加空格**（中文界面，非中英混排技术文档场景）
- 数值一律 `font-variant-numeric: tabular-nums` 且**右对齐**，保证列内小数点对齐
- 域名、哈希、耗时、ffmpeg 输出一律 `--font-mono`

## 4. Components

### 4.1 按钮

| 变体 | 背景 | 文字 | 边框 | 用途 |
|---|---|---|---|---|
| Primary | `--accent` | `--accent-on` | 无 | 主操作（每屏 1 个） |
| Secondary | `--surface` | `--fg` | 1px `--border` | 次操作 |
| Ghost | transparent | `--muted` | 无 | 工具条图标按钮、表格行内操作 |
| Danger | transparent | `--danger` | 1px `--danger-border` | 删除任务/清空队列 |

几何：高度 28 / 32 / 40px；横向内边距 8 / 12 / 16px；圆角 `--radius-md` (6px)；字号 13px / 字重 510。

**状态矩阵（9 态）：**

| 状态 | 规格 |
|---|---|
| Default | 见上表 |
| Hover | 背景切换，`--motion-fast` 150ms 过渡 |
| Focus-visible | `--focus-ring`（2px 底色环 + 4px accent 环），**不移除默认 outline 除非提供等价 ring** |
| Active | `--btn-primary-bg-active` / `--btn-secondary-bg-active`，无位移 |
| Disabled | `opacity: var(--opacity-disabled)` (0.45)，`cursor: not-allowed`，**必须同时禁用 pointer 事件** |
| Loading | 文字替换为 16px spinner（图标 `loader`，`animation: spin 800ms linear infinite`）+ 保留原文字宽度防止布局抖动；按钮 disabled |
| Error | 仅表单提交按钮：`--danger` 描边 + 下方 inline 错误文案 |
| Empty | 不适用（按钮本身无空态） |
| Success | 短任务成功后按钮内 `check-circle` 图标停留 1.2s 后复原，不弹 Toast |

### 4.2 输入框

高度 32px；圆角 6px；背景 `--bg-sunken`（比面板更深，形成凹陷感）；边框 1px `--border`。

| 状态 | 规格 |
|---|---|
| Default | `--input-bg` / `--input-border` |
| Hover | `--input-border-hover` |
| Focus | 边框转 `--accent` + `--input-ring-focus` |
| Error | 边框 `--danger`，下方 12px `--danger` 文案，**错误信息紧贴字段不堆到顶部** |
| Disabled | `--input-bg-disabled` + `--input-fg-disabled` |
| ReadOnly | 无边框，背景 transparent，文字 `--fg-2` |

**表单规则：** 必须可见 `<label>`，**禁止只用 placeholder 当标签**；必填字段 label 后加 `--danger` 星号；错误文案用具体动词，如「ffmpeg 路径不存在，请检查设置页的路径配置」而非「输入无效」。

### 4.3 面板 / 卡片（Density 7 的关键约束）

```
静态面板 = 1px 边框 + 无阴影。  禁止同时出现 1px 边框与 blur≥16px 阴影（幽灵卡片禁令）。
浮层（Dropdown / Popover / Modal / Toast）= 阴影 + 1px ring，允许组合。
```

- 面板圆角 `--radius-lg` (8px)，**上限 16px**
- 面板内边距 `--space-4` (16px)
- **禁止彩色左边框强调**（`border-left: 3px solid accent` 是 AI 设计特征）——用整框 `--border-accent` 或选中底 `--surface-selected` 表达选中
- 数据分组用 `border-top: 1px solid var(--divider)`，**不给每条数据套卡片盒**

### 4.4 表格行 / 结果行

| 类型 | 行高 | 规则 |
|---|---|---|
| 紧凑行（任务队列、日志） | 28px | hover `--row-bg-hover`，selected `--row-bg-selected` + 左侧 2px `--border-accent` |
| 结果行（含缩略图） | 72px | 缩略图 96×54 圆角 4px；标题最多 2 行截断；右侧数值列固定宽度右对齐 |

### 4.5 Badge / Tag

高度 20px，横向内边距 6px，圆角 4px，字号 12px / 字重 510。

| 变体 | 用途 |
|---|---|
| neutral | 文件格式、分辨率、帧率 |
| accent | **跨引擎交叉验证徽章**（`×2` `×3`） |
| success | 哈希相似度 ≥90% |
| warn | 部分降级 / 限频中 |
| danger | 引擎失败 |

### 4.6 拖拽上传区

- 背景 `--dropzone-bg`（比页面更深的凹槽），圆角 12px
- 边框 **2px 虚线** `--dropzone-border`；hover 转 `--dropzone-border-hover`
- 拖拽悬停时：边框转 `--accent` 实线 + 背景 `--dropzone-bg-active`，`--motion-fast` 150ms
- 内部：24px `upload` 图标 + 18px 主文案 + 13px 副文案 + 底部三个入口（选择文件 / 粘贴路径 / 拖到此处）
- **无障碍**：必须是真实 `<input type="file">`（视觉隐藏但可 focus），外层 `<label>`；键盘 Tab 可达 + Enter 触发文件选择器
- **松手即启动**：不弹确认框，直接创建任务并跳转任务详情

### 4.7 进度条 / 骨架屏

- 进度条高 4px，圆角 4px，填充 `--progress-fill`
- **不确定进度**（引擎查询中，未知总量）：用 `--ease-linear` 的无限滑动微光（1.2s），**不用转圈 spinner**（转圈在长任务中会误导）
- 骨架屏：`--skeleton-bg` 底 + `--skeleton-shine` 微光扫过，`--ease-linear` 1.4s 循环；**骨架块尺寸必须等于真实内容尺寸**，避免 CLS

### 4.8 Toast

- 位置：右下角，距边 16px；堆叠上限 3 条
- 背景 `--toast-bg`，边框 1px `--toast-border`，阴影 `--toast-shadow`，圆角 8px
- 结构：20px 状态图标 + 文案（≤40 字）+ 可选 1 个操作按钮 + 关闭 `x` 图标
- 进入 `--motion-base` 200ms 从右滑入 + 淡入；自动消失 4s（含操作按钮的 8s）
- **禁止**：顶部居中横幅式 Toast；同一错误重复堆叠（相同 message 去重）

### 4.9 Modal

- 遮罩 `rgba(1,4,9,0.65)`（深色）/ `rgba(31,35,40,0.4)`（浅色），点击遮罩关闭
- 面板最大宽 480px / 640px 两档，圆角 12px，阴影 `--elev-modal`
- 进入：遮罩淡入 150ms + 面板 scale 0.98→1 淡入 200ms（`--ease-standard`）
- **必须**：打开时焦点移入面板首个可聚焦元素；Esc 关闭；关闭后焦点回到触发元素；焦点在面板内循环（focus trap）
- 移动端 <768px：改底部 ActionSheet（圆角仅顶部 12px，从下滑入）

## 6. Depth & Elevation

### 6.1 阴影阶梯

| Token | 深色值 | 用法 |
|---|---|---|
| `--elev-flat` | `none` | 静态面板默认（配 1px 边框） |
| `--elev-ring` | `0 0 0 1px var(--border)` | 静态面板描边 |
| `--elev-raised` | `0 3px 6px rgba(1,4,9,0.40)` | 浮起卡片（**不配 1px 边框**） |
| `--elev-overlay` | `0 8px 24px rgba(1,4,9,0.60), 0 0 0 1px var(--border)` | Dropdown / Popover |
| `--elev-modal` | `0 16px 48px rgba(1,4,9,0.75), 0 0 0 1px var(--border)` | Modal |

**硬规则：** 静态面板/卡片上，`1px 边框` 与 `blur ≥16px 的阴影` **不得同时出现**。"幽灵卡片"（淡边框 + 大模糊阴影）是明确的 AI 味特征，前端实现时逐元素检查。

### 6.2 深色模式的层级表达

**用亮度递进代替阴影**（深色下阴影几乎不可见）：

```
背景层：  #010409 (bg-sunken)  →  #0D1117 (bg)  →  #161B22 (surface)  →  #1C2129 (surface-raised)
文本层：  #E6EDF3 (fg)  →  #ADBAC7 (fg-2)  →  #8B949E (muted)  →  #768390 (meta)
边框层：  #21262D (border-soft)  →  #30363D (border)  →  #444C56 (border-strong)
```

**不使用装饰性毛玻璃。** 唯一允许 `backdrop-filter` 的场景：Modal 遮罩（且需 `@supports` 回退到纯色半透明）。

### 6.3 Z 轴

`base 0` / `sticky 100` / `dropdown 1000` / `overlay 1100` / `modal 1200` / `toast 1300`

## 7. Do's & Don'ts

### 应该做

1. **每个数字都能溯源**：相似度、排名、耗时、命中数必须能在 UI 上看到它是哪个引擎、哪次查询产生的。
2. **不确定性显式可见**：引擎降级、结果缺失、限频冷却——全部用 §12 的规范标出来，不静默吞掉。
3. **数据列用等宽字体右对齐**：数值扫读靠列对齐，不靠逐个读。
4. **1px 线分组，不给数据套卡片盒**（Density 7）。
5. **状态双重编码**：颜色 + 图标形状，色盲可读。
6. **长任务用确定性进度 + 不确定微光区分**：抽帧（已知总帧数）用百分比进度条；引擎查询（未知耗时）用滑动微光。
7. **空状态给动作**：每个空状态都配一个可执行按钮（上传 / 重试 / 改配置）。
8. **键盘全程可达**：上传区、帧网格、结果列表、模态框、下拉。

### 不应该做

1. **不用 emoji 作功能图标**（P0）。全部走 §14 的 SVG sprite。
2. **不用紫色→粉色渐变**（P0）。本项目**不使用任何装饰性渐变**，唯一允许的渐变是进度条填充（同色深浅）。
3. **不用居中大 Hero + 三卡片**（P0）。首屏是真实上传区 + 真实任务列表。
4. **不写空洞文案**：禁止「欢迎使用」「强大的视频溯源工具」「开启您的溯源之旅」。全部用具体动作与具体名词。
5. **不用彩色左边框强调卡片**（`border-left: 3px solid`）— AI 设计特征。
6. **不用渐变文字**（`background-clip: text` + 渐变）— 用纯色 + 字重/字号强调。
7. **不编造指标**：禁止「已索引 10 亿张图」「准确率 99.9%」这类无来源数字。所有数字来自真实运行结果。
8. **不用装饰性毛玻璃 / 发光边框**。
9. **不重复结构动效**：不要每个 section 都用同样的淡入；每个动画应匹配它揭示的内容。
10. **不用奶油/米色背景**：温暖感由强调色与排版传达，不由背景色传达。

### 8.1 断点行为

| 断点 | 布局 |

| 768–1024px | Sidebar 折叠为 56px 图标栏；Inspector 转抽屉；帧网格 2 列 |

| >1280px | 完整三栏；帧网格 3–4 列；容器居中最大 1440px |

### 8.2 无障碍清单

| 项 | 要求 |
|---|---|
| 对比度 | 正文 ≥4.5:1（§2.1 已核验全部 token 达标）；非文本 UI 组件 ≥3:1 |
| 焦点可见 | `:focus-visible` 用 `--focus-ring`（2px 底色环 + 4px accent 环）。**禁止 `outline: none` 而不提供替代** |
| 键盘导航 | Tab / Shift+Tab 全程可达；帧网格与结果列表支持 ↑↓←→ 移动焦点、Enter 打开、Space 选中 |
| 图标按钮 | 必须有 `aria-label`（中文）。纯图标按钮不可无标签 |
| 状态双重编码 | 引擎状态 = 颜色 + 图标形状，不单靠颜色 |
| 表格语义 | 用 `<table>` + `<th scope>`，或 `role="grid"` + `aria-rowindex` |
| 进度反馈 | 任务进度用 `role="progressbar"` + `aria-valuenow` + `aria-live="polite"`（每 10% 播报一次，不要每帧播报） |
| 降级提示 | 提示条用 `role="status"`（非错误）/ `role="alert"`（全部失败） |
| 减弱动效 | `@media (prefers-reduced-motion: reduce)` 关闭全部动画（CSS 已在 token 文件中落地） |
| 触摸目标 | `@media (pointer: coarse)` 下 ≥44×44px |
| 缩放 | 允许 `user-scalable=yes`，**禁止禁用缩放** |

### 8.3 五态覆盖要求

**每个视图必须同时给出 Loading / Empty / Error / Populated / Edge 五态设计**（§11 逐页列明）。额外要求本产品专属的第 6 态：**Degraded（部分降级）**——见 §12。

### 9.3 实现坑位提醒

1. **图标 sprite 必须内联在首个 HTML 响应里**，不要异步加载——否则首屏图标闪空。
2. **字体本地托管**，`font-display: swap`，禁 Google Fonts CDN（离线场景）。
3. **CSS 变量不能被 Tailwind 的 `<alpha-value>` 语法直接透明化**；需要透明度时用 `color-mix(in srgb, var(--accent) 12%, transparent)` 或预定义的 `*-dim` token。
4. **长列表必须虚拟滚动**：帧网格 >100 帧、结果列表 >200 条时启用，行高固定（28 / 72px）以便计算。
5. **进度条不要动画 width/height**（触发布局），动画 `transform: scaleX()`。
6. **CLS 控制**：帧缩略图容器固定宽高比 `aspect-ratio: 16/9` + 骨架占位，图片加载完成不改变布局。
7. **轮询节流**：引擎状态轮询 ≥1s 间隔，且用 `requestAnimationFrame` 合批更新，避免长任务下 UI 卡顿。
8. **相似度为 null 必须显式渲染**：后端无该数值时显示 `—`（em dash）而非 `0%` 或 `NaN`，并在 tooltip 说明原因。

### 11.6 关键空状态：语义必须准确（**禁止写"未找到来源"**）

反向图搜最容易误导用户的地方就是空结果。TinEye 官方明确说明：**没有结果 ≠ 这张图是原创的**，只代表它不在该引擎的索引里。本产品必须原样传达这个语义。

**标准空结果态（中栏）：**

```
        [image-off 24px, meta 色]

   3 个引擎均未在当前索引中找到匹配

   这不代表视频内容是原创的 —— 只说明这 128 帧
   没有命中 Google Lens / Bing / Yandex 的公开索引。
   社交平台、付费素材库与未收录页面不在索引范围内。

   [重新查询]   [调整抽帧密度]   [查看引擎诊断]
```

**文案规则：**
- 用「{N} 个引擎均未在当前索引中找到匹配」，**不用**「未找到来源」「查无此图」
- 必须说明**影响范围**（哪个引擎、多少帧）
- 必须给出**下一步**（至少 2 个动作按钮）
- **禁止**任何暗示"已证明原创/无侵权"的表述

### 11.7 四种空状态必须区分（PRD §9 边界条件）

> PRD 原文：无任务、抽帧 0 帧、搜索 0 命中、筛选后 0 条 —— **分别解释原因与下一步，不得用同一空文案**。

| # | 场景 | 标题 | 说明文案 | 动作按钮 |
|---|---|---|---|---|
| 1 | **无任务** | 还没有任务 | 拖入一个 MP4 / MOV / WEBM 视频，或点击选择文件。原视频始终留在本机。 | Primary「选择视频文件」／ Ghost「查看支持的格式」 |
| 2 | **抽帧 0 帧** | 没有抽出可用的帧 | 场景变化模式未检测到足够的画面切换（{N} 秒内变化阈值未触发）。可改用固定间隔模式，或降低变化阈值。 | Primary「改用固定间隔重试」／ Secondary「调整变化阈值」 |
| 3 | **搜索 0 命中** | {N} 个引擎均未在当前索引中找到匹配 | 这不代表视频内容是原创的 —— 只说明这 {M} 帧没有命中 {引擎列表} 的公开索引。社交平台、付费素材库与未收录页面不在索引范围内。 | Primary「换一批帧重试」／ Secondary「更换引擎」／ Ghost「查看引擎诊断」 |
| 4 | **筛选后 0 条** | 当前筛选条件下没有结果 | 已命中 {N} 条，但都被当前筛选条件排除（{当前筛选摘要}）。 | Primary「清除全部筛选」／ Ghost「仅放宽相似度阈值」 |

**共同规则：**
- 四个空状态的图标**必须不同**：① `film` ② `frame` ③ `search-x` ④ `filter` —— 让用户在扫视时就能分辨是哪一类空
- 图标 24px，`--meta` 色；标题 16px/510；说明 13px `--muted`，最多 3 行
- **禁止**把 3 和 4 合并成「暂无数据」
- **禁止**在场景 3 中出现任何暗示「已证明原创 / 无侵权」的表述（对应 PRD §13 风险与 §12.2 发布阻断条件）

**部分空态（某几帧无结果）：** 不用整页空态，改用中栏顶部的 DegradedBanner（info 级）：「{M} 帧中有 {K} 帧为零结果，已折叠显示」+ 次要按钮「仅显示有结果的帧」+「把这些帧标记为已跳过」。

## 12. 降级态视觉规范（重点）

**设计原则：降级不是错误，是信息。** 三个引擎各有各的失败方式（网络不可达、风控、限频、超时、反爬），用户需要知道**哪个引擎、影响了什么、接下来会怎样**。静默吞掉失败 = 让用户对结果可信度产生错误判断。

### 12.1 结果分类：成功 / 降级 / 失败三族（PRD §5.2 P0-B / EARS #13）

**先分清族，再看级别。最容易出错的是把「成功零结果」混进降级或失败。**

| 族 | 状态 | 判定 | 是否计入失败 | 主色 |
|---|---|---|---|---|
| **成功族** | 成功有结果 | 引擎正常响应且返回 ≥1 条候选 | 否 | `--status-hit`（绿） |
| **成功族** | **成功零结果** | 引擎正常响应但返回 0 条候选 | **否 —— 这是一次成功的检索，只是没命中** | `--status-zero`（**中性灰，非绿非红**） |
| **降级族** | 限频 / 需验证码 / 解析异常 / 网络错误 | 请求未完成或结果不可用 | 是（可恢复） | `--warn` / `--danger` |
| **失败族** | 凭据错误 / 引擎不可用 | 需要用户改配置才能继续 | 是（需干预） | `--danger` |

**硬性规定（对应 PRD 发布阻断条件「把空结果展示为命中、伪造相似度或隐藏 provider 错误」）：**

1. **「成功零结果」既不能用绿色，也不能用红色。** 用绿 = 伪装成命中；用红 = 让用户以为服务坏了。必须用中性色 `--status-zero` + 专属图标 `search-x` + 文案「零结果」。
2. **零结果不得伪造命中数量或候选链接**，也不得显示「0 条命中，已为你找到相似内容」这类填充内容。
3. **零结果必须给可行动建议**：换帧重试 / 换引擎 / 调整抽帧密度 —— 对应 PRD GWT #7「提供更换帧/引擎建议」。

**任务级四级分类：**

| 级别 | 名称 | 判定条件 | 是否阻断任务 | 主色 |
|---|---|---|---|---|
| **L0** | 全部完成 | 所有「帧 × 引擎」项为成功族（有结果或零结果） | 否 | 无提示 |
| **L1** | 部分完成 | ≥1 个引擎降级或失败，但 ≥1 个引擎有结果 | **否**（对应 EARS #11：标记为「部分完成」而非「全部失败」） | `--warn` |
| **L2** | 引擎不可用 | 某个引擎整体不可用（provider 级熔断） | **否**（其他引擎继续） | `--warn` |
| **L3** | 全部失败 | 所有已选引擎均不可用（**注意：全部「零结果」不算 L3，算 L0**） | 标记失败，**保留已抽帧** | `--danger` |

**关键规则：** L1/L2 **不阻断任务**，任务继续跑完并给出结果；**不得因后续单项失败回滚已成功项**（EARS #9）。即使 L3，**已抽取的帧必须保留**，并提供「稍后继续 / 更换引擎 / 手工检索指引」三类可行动选项（EARS #12）。

### 12.2 「帧 × 引擎」十一态规范（PRD §5.2 P0-B）

**这是本产品最核心的 UI 契约。** PRD 明确要求每个「帧 × 引擎」组合显示唯一状态，覆盖：待处理、发送中、成功有结果、成功零结果、限频、需验证码、凭据错误、网络错误、解析异常、已跳过、已取消。

| # | 状态 | 英文 key | 颜色 Token | 图标 | 状态文案模板 | 建议动作 | 动画 |
|---|---|---|---|---|---|---|---|
| 1 | 待处理 | `pending` | `--status-pending` | `clock` | 待处理 | 开始 / 移除 | 无 |
| 2 | 发送中 | `sending` | `--status-sending` | `send` | 发送中 | 取消此项 | 状态点脉冲 1.4s（**唯一允许的持续装饰动画**） |
| 3 | **成功有结果** | `hit` | `--status-hit` | `check-circle` | 命中 {N} 条 | 查看结果 | 无 |
| 4 | **成功零结果** | `zero` | `--status-zero` | `search-x` | 零结果 | 换帧重试 / 换引擎 | 无 |
| 5 | 限频 | `rate_limited` | `--status-ratelimited` | `zap` | 限频 · 冷却 {N}s | 等待自动继续 / 稍后重试 | 倒计时每 1s 更新 |
| 6 | 需验证码 | `captcha` | `--status-captcha` | `shield-alert` | 需人工验证 | **转手工检索** | 无 |
| 7 | 凭据错误 | `credential` | `--status-credential` | `key` | 凭据无效 | 检查密钥配置 | 无 |
| 8 | 网络错误 | `network` | `--status-network` | `cloud-off` | 网络不可达 | 检查网络后重试 | 无 |
| 9 | 解析异常 | `parse` | `--status-parse` | `alert-triangle` | 返回结构异常 | 重试 / 停用此引擎 | 无 |
| 10 | 已跳过 | `skipped` | `--status-skipped` | `ban` | 已跳过 | 恢复此项 | 无 |
| 11 | 已取消 | `cancelled` | `--status-cancelled` | `ban` | 已取消 | 恢复此项 | 无 |

**配套规则：**

| 规则 | 说明 |
|---|---|
| **不得无限自动重试** | 对应 EARS #10。每个失败项最多自动重试 `maxRetry`（默认 3），超出后转为「需人工决定」并展示「重试 {i}/{max}」 |
| **需验证码 = 转人工，不绕过** | 对应 PRD 合规红线。`captcha` 状态下**禁止**提供「自动重试」按钮，只提供「手工检索指引」（打开该引擎网页 + 提示手动上传本帧）+「跳过此项」。**这是硬约束，不是建议。** |
| **可重试时间可见** | 若引擎返回 `Retry-After`，显示具体秒数倒计时；未返回时显示「建议 {N} 分钟后重试」（由本地退避策略估算，并标注「估算」） |
| **已完成结果不得回滚** | 对应 EARS #9。任一项失败不影响其他项已保存的结果 |
| **失败原因展示原始类型** | 显示 `429 / 401 / 403 / 超时 / DNS 失败` 等具体类别，不统一显示「搜索失败」 |

**双重编码（无障碍强制，PRD §10 可访问性）：** 状态由 **颜色 + 图标形状 + 文案** 三重表达。Chip 结构：`[状态点 8px] [图标 16px] [引擎名 13px/510] [状态文案 12px muted]`。

**Chip 容器：** 高 24px，圆角 `--radius-full`，背景 `--surface-warm`，边框 1px 透明。非成功族状态（5–9）时边框转为对应状态色 45% 透明度，背景转为对应 dim 色。**`zero` 状态不加边框强调**（它不是异常，只是没命中）。

**引擎级聚合（provider 健康度）**：由该引擎下所有帧的十一态聚合而来，用于 TopBar 健康条与 EngineCard：
`idle`（全部待处理）/ `running`（有发送中）/ `ok`（全部为成功族且有命中）/ `zero`（全部为成功零结果）/ `throttled`（有限频）/ `failed`（有凭据错误或全部网络错误）/ `disabled`（已停用）。
**`zero` 必须单独显示** —— 引擎健康但一个都没命中，与「引擎坏了」是完全不同的信息。

### 12.3 全局降级提示条（DegradedBanner）规范

**位置：** 结果列表顶部，**sticky**（`position: sticky; top: 0`），不遮挡上传区，**非模态**，不拦截操作。

**结构（单行，高度自适应，最大 2 行文案）：**

```
┌────────────────────────────────────────────────────────────────────┐
│ [图标20] 主文案（13px/510）                    [动作按钮] [x 关闭]  │
│          明细（12px muted，可折叠展开，默认收起）                    │
└────────────────────────────────────────────────────────────────────┘
```

**三个层级：**

| 层级 | Token | 图标 | 触发 | 文案模板 |
|---|---|---|---|---|
| **info** | `--degraded-info-*` | `zap` | 限频排队 | 「达到 Bing 的请求上限，剩余 {N} 个查询将在 {S} 秒后自动继续」+ 动作「立即重试」 |
| **warn**（L1/L2） | `--degraded-warn-*` | `alert-triangle` | 部分引擎降级 | 「3 个引擎中 1 个未返回结果，以下结果来自 Google Lens 与 Bing」+ 明细「Yandex 请求超时，已重试 2 / 3 次（耗时 8.4s）」+ 动作「重试 Yandex」/「稍后自动重试」 |
| **danger**（L3） | `--degraded-danger-*` | `x-circle` | 全部引擎失败 | 「3 个引擎均未返回结果，可能是网络不可达或触发风控」+ 明细「已保留抽取的 128 帧，修改配置后可直接重新查询，无需重新抽帧」+ 动作「全部重试」/「查看引擎诊断」 |

**提示条内容强制三要素（缺一不可）：**

1. **发生了什么** —— 点名具体引擎，不写"部分服务异常"
2. **影响是什么** —— 结果来自哪几个引擎、少了多少、可信度如何变化
3. **下一步是什么** —— 自动重试（含倒计时）/ 手动重试 / 改配置 / 查看诊断

**视觉规格：**
- 边框 **1px**（对应层级 border token）；背景为对应 dim 色；圆角 8px；内边距 12px 16px
- 图标 20px，颜色为对应 fg token
- **不使用阴影**（静态元素）
- 入场：`--motion-base` 200ms 从上滑入 + 淡入；**不做闪烁、不做脉冲**
- 关闭：用户手动关闭后**同一任务内不再自动弹出**（记录 dismissed 状态），但状态点仍然保留在 TopBar

**禁止项：**
- 禁止只写「出错了」而无原因
- 禁止只有红色而无可执行动作
- 禁止用模态弹窗阻断（用户可能只是想看已有结果）
- 禁止同一降级重复弹 Toast（提示条即播报，Toast 仅用于操作反馈）

### 12.4 帧缩略图角标（帧级降级）

帧网格中每格左上角 12px 角标（背景为 `--surface` 的 12px 圆形底，保证在任意缩略图上可读）：

| 帧状态 | 角标 | 缩略图处理 |
|---|---|---|
| 全部引擎成功 | 无角标 | 正常 |
| 部分引擎失败 | `alert-triangle` 12px，`--warn` | 正常 |
| 全部引擎失败 | `x-circle` 12px，`--danger` | `opacity: 0.55` + `filter: grayscale(0.4)` |
| 未开始查询 | 无角标 | `--skeleton-bg` 灰块占位 |
| 查询中 | `loader` 12px，`--engine-running` | 正常 + 底部 2px 滑动微光进度 |

角标必须带 `aria-label`（中文描述，如「第 47 帧：Yandex 超时，其余引擎正常」）。

### 12.5 引擎分组内的 inline 失败行

在帧溯源详情的逐引擎 Tab 中，失败引擎**不显示空白**，而是显示一行 inline 状态行（高 48px）：

```
┌────────────────────────────────────────────────┐
│ [x-circle 20px danger] Yandex 未返回结果        │
│ 请求超时（已重试 3/3，耗时 24.1s）              │
│                                    [重试此引擎] │
└────────────────────────────────────────────────┘
```

- 背景 `--danger-dim`，左侧**无**彩色边框（遵守彩色左边框禁令），用整框 1px `--danger-border`
- 动作按钮为 Secondary（非 Primary，因为主操作属于全局）

### 12.6 降级态的动效约束

| 场景 | 动效 | 时长 |
|---|---|---|
| 提示条入场 | 下滑 + 淡入 | 200ms `--ease-standard` |
| 引擎状态点 running | 脉冲（`opacity` + `scale`，不动画布局属性） | 1400ms infinite |
| 限频倒计时 | 数字每秒更新，**无过渡动画** | — |
| 重试图标 | 旋转 | 800ms `--ease-linear`，仅重试瞬间 |
| 失败帧缩略图 | 灰度 + 透明度 | 150ms `--ease-standard` |
| 提示条关闭 | 上滑 + 淡出 | 150ms |

**全部动画在 `prefers-reduced-motion: reduce` 下关闭**（CSS 已在 token 文件落地）。running 脉冲在减弱动效模式下改为**静态实心点**。

## 13. 相似度双数值展示规范（重点）

### 13.1 两个数值的语义区分（先说清楚，再设计）

| 数值 | 来源 | 语义 | 单位 | 可跨引擎比较 | 可靠性 |
|---|---|---|---|---|---|
| **引擎排序位置** | 引擎返回列表中的位次 `rank / total` | 「引擎认为它有多靠前」 | 序数（第 N 名） | **否**（各引擎 total 不同） | 反映引擎内部置信，但受引擎自身排序策略影响 |
| **本地哈希相似度** | 本地 pHash / dHash 与来源图的汉明距离换算 | 「像素级有多像」 | 比率 0–100% | **是**（同一算法） | 反映视觉相似，但无法判断是否为同一来源 |

**为什么两个都要显示（不能合成一个分数）：**

- 排序位置**高但哈希低** → 引擎认为是同一个语义对象（比如同一场景的不同截图），但像素不像 → 是语义相关，不是同一份文件
- 排序位置**低但哈希高** → 像素几乎一致，但引擎把它排在后面（可能是冷门页面）→ 可能是真正的原图，只是权重低
- 只看任一个都会误判。**合成一个分数 = 制造黑箱**，与"溯源取证"的产品性质冲突。

因此规则：**排序可以用排序分（线索分），但两个原始数值必须始终同时可见。**

### 13.1b 分数来源标注（PRD §5.2 P0-C 硬性要求）

> PRD 原文：相似度必须标识来源 —— `引擎提供`、`本地归一化` 或 `无分数`，**不得展示伪精确百分比**。

**每个数值旁边必须带一个来源标签**，字体 11px mono，三种取值：

| 标签 | Token | 含义 | 展示规则 |
|---|---|---|---|
| `引擎提供` | `--score-source-engine` | 数值直接来自引擎返回字段 | 必须同时给出原始字段名（如 `Google Lens 第 3 名`） |
| `本地归一化` | `--score-source-local` | 本应用计算（pHash 汉明距离换算） | 必须同时给出原始度量（如 `汉明距离 6 / 64`） |
| `无分数` | `--score-source-none` | 引擎未提供、本应用也不推断 | 显示 `—`，**禁止填 0、禁止估算、禁止显示百分比条** |

**禁止的伪精确表现（逐条对照）：**

| 禁止 | 原因 |
|---|---|
| 把不同引擎的原始分直接换算成统一百分比 | 各引擎分数量纲不同，**不可横向比较**（PRD §13 风险项） |
| 无分数时显示「相似度 0%」 | 0% 是断言，而真实情况是「未提供」 |
| 排序分显示为「匹配置信度 87%」 | 它不是概率。维权用户会读成「有 87% 概率这是原作者」，那是灾难（反例） |
| 小数位超过 1 位 | 本地启发式没有这个精度。哈希相似度用整数百分比，排序分保留 2 位小数 |

#### 命名分层（PM 已裁定，PRD §5.2 P0-C + EARS #17b）

同一个分数，**界面标签与数据字段名用两个词，这是有意为之，不是二选一的分歧**：

| 层 | 用词 | 出现位置 | 理由 |
|---|---|---|---|
| **界面标签** | **排序分** | 排序下拉、结果行、Inspector、提示条 | 「排序分」只描述它干什么（用于排序），C 类用户（内容编辑）一眼能懂 |
| **数据字段名 / 帮助说明 / 导出 / PRD** | **线索分** | CSV/JSON 列名、帮助面板、设置页权重说明、PRD | 「线索」描述它**不是什么**（不是结论），是产品对外承诺的一部分（PRD §3.4「线索而非结论」），不能只因为抽象就丢掉 |
| 二者关系 | 同义 | — | 帮助说明里保留「线索分」表述，界面标签写「排序分」 |

**展示规格：**
- 界面标签：`排序分 0.87`
- 下方 11px 说明：`排序分（数据字段：线索分）仅用于排序，不代表来源真实性概率，需人工核验`
- 排序下拉下方写明公式：`排序分 = 跨引擎命中 45% + 跨帧命中 20% + 本地哈希 35%`（权重可调，默认按 PRD §5.2「跨引擎命中数—跨帧命中数—首次出现顺序」的稳定排序精神设定）

**硬性禁用措辞（EARS #17b 可验收项，不是文案建议）：**
`匹配度` / `置信度` / `准确率` / `命中概率` —— 这四个词在**任何**面向用户的界面、提示、导出列名中均不得出现。

### 13.2 结果行中的双数值单元（紧凑，单行内）

放在结果行右侧**固定 160px 宽**的列内，等宽字体，`tabular-nums`，右对齐：

```
┌────────────────────────┐
│ 第 3/47   ▓▓▓▓▓▓░░░░  │   ← 排名行：13px mono，--fg-2
│ 哈希 92%  ▓▓▓▓▓▓▓▓░░  │   ← 哈希行：13px mono + 徽章色
└────────────────────────┘
```

**逐项规格：**

| 元素 | 规格 |
|---|---|
| 排名行标签 | 「第 3/47」，13px mono `--fg-2`；`total` 未知时显示「第 3 名」 |
| 排名来源标注 | 标签右侧 11px mono `引擎提供`（`--score-source-engine`） |
| 排名百分位 | 不直接显示数字（避免与哈希数值混淆），**只用 2px 高的 micro-bar 长度**表达：`(1 - rank/total) × 100%` |
| 排名 micro-bar | 宽 40px，高 2px，圆角 1px；轨道 `--rank-track`，填充 `--rank-fill`（**恒用中性色**） |
| 哈希行标签 | 「哈希 92%」，13px mono；数值部分字重 590，**颜色按阈值变化**：≥90% `--success` / 70–89% `--fg-2` / <70% `--meta` |
| 哈希来源标注 | 标签右侧 11px mono `本地归一化`（`--score-source-local`）；若引擎也提供了分数，额外显示 `引擎提供` 标签 |
| 哈希 micro-bar | 宽 40px，高 2px；轨道 `--score-track`，填充按同一阈值取 `--score-fill-high/mid/low` |
| 缺失值 | 任一数值为 null → 显示 `—`（em dash）+ `无分数` 标签（`--score-source-none`），**micro-bar 不渲染**，tooltip 说明「{引擎名} 未返回排名信息」 |
| 数据缺失（PRD §9） | 无标题显示「未提供标题」、无缩略图显示 `image-off` 占位 + 「未提供缩略图」——**一律标「未提供」，不得补造、不得留空** |
| tooltip | 悬停整个单元显示：`引擎排序位置：Google Lens 第 3 名（共 47 条）` / `本地哈希相似度：92%（pHash 汉明距离 6）` |

**关键决策：颜色只给哈希相似度，排名条恒用中性色。**
理由：两条彩色条并排 = 视觉噪音，且会让人误以为两个数值同等可靠。让哈希条承担"质量"语义（绿=高），让排名条只承担"位置"语义（长度表达），层次才清楚。

### 13.3 跨引擎交叉验证徽章（第三信号，最强置信信号）

同一 URL（归一化后：去协议、去 `www.`、去 query、去末尾斜杠）被 **≥2 个引擎**命中时，在标题行右侧显示 accent 描边徽章：

```
  视频标题示例文字                                    [×3]
  example.com                                      ↑ accent badge
```

- 徽章：`×{N}`，高度 20px，`--badge-accent-bg` 底 + `--badge-accent-border` 描边 + `--badge-accent-fg` 文字，12px/510
- tooltip：「3 个引擎独立命中此页面：Google Lens（第 1 名）、Bing（第 3 名）、Yandex（第 5 名）」
- 排序权重：**交叉验证数的权重高于任一单数值**（见 §13.4）

**这是多引擎聚合工具相对单引擎工具的核心优势**，来自调研结论：「出处的判断，要靠多个工具交叉比对，不能只看单一工具的结论」。UI 必须把它做成一等公民，而不是角落里的一行小字。

### 13.4 排序键（5 项，下拉选择）

| 排序键 | 计算 | 默认 |
|---|---|---|
| **排序分**（推荐，数据字段名 `线索分`） | `0.45 × 跨引擎命中归一 + 0.20 × 跨帧命中归一 + 0.35 × 本地哈希相似度` | **是** |
| 跨引擎命中数 | 命中引擎数降序 | |
| 跨帧命中数 | 命中帧数降序 | |
| 本地哈希相似度 | 本地哈希相似度降序（仅 `本地归一化` 来源，可比） | |
| 首次出现顺序 | 首次命中时间戳升序（对应 TinEye 的 Oldest 排序语义） | |

**稳定排序规则（PRD §5.2 P0-C）：** 排序分同分时，依次按 `跨引擎命中数 → 跨帧命中数 → 首次出现顺序` 排序，保证每次渲染顺序一致。

**排序分必须可解释：** 排序下拉下方 12px muted 说明「排序分 = 跨引擎命中 45% + 跨帧命中 20% + 本地哈希 35%」，点击「调整权重」打开设置面板（三个滑块，实时预览前 10 条重排）。**禁止黑箱排序。**

**命名硬性规定（EARS #17b 可验收项）：**
- **界面标签一律写「排序分」**，帮助说明与导出列名写「线索分」，两者同义
- **禁用措辞**：`匹配度` / `置信度` / `准确率` / `命中概率`
- 每一处出现排序分的界面，同屏必须可见「不代表来源真实性概率，需人工核验」（结果列表顶部一行 12px muted 常驻即可，不必每行重复）

### 13.5 Inspector 中的双数值明细块

右栏 Inspector 内展开显示（不像列表那样压缩）：

```
┌────────────────────────────────────────┐
│ 排序依据                                │  16px/510
├────────────────────────────────────────┤
│ 交叉验证        3 个引擎独立命中        │  accent 徽章 ×3
│ 引擎排序位置    Google Lens 第 3 / 47   │  13px mono
│                 Bing      第 1 / 23     │
│                 Yandex    第 5 / 61     │
│ 本地哈希相似度  92%                     │  success 色，590 字重
│                 pHash 汉明距离 6 / 64   │  12px meta mono
├────────────────────────────────────────┤
│ 排序分 0.87                             │  13px mono，--fg
│ ────────────────────────────────────── │
│ 排序分（数据字段：线索分）仅用于排序，  │  11px --meta
│ 不代表来源真实性概率，需人工核验        │
└────────────────────────────────────────┘
```

- 每行用 `border-top: 1px solid var(--divider)` 分隔，**不套卡片盒**
- 引擎排序位置逐引擎列出（这才是"多引擎"的真相，平均值会掩盖差异）
- 哈希相似度同时给出**原始汉明距离**（可核查，不只是一个百分比）
- 排序分放在最后，**下方必须常驻免责说明**（11px `--meta`）：「排序分（数据字段：线索分）仅用于排序，不代表来源真实性概率，需人工核验打开源页」
- 每个数值行右侧带来源标签（`引擎提供` / `本地归一化` / `无分数`）

### 13.6 数值展示的禁止项

- **禁止**只显示合成分而隐藏两个原始数值
- **禁止**用百分比条表达排名（排名是序数，不是比率；用长度表达位置已是极限）
- **禁止**两个数值都用彩色
- **禁止**把哈希相似度写成「相似度 92%（高）」这类形容词后缀——数字自己会说话
- **禁止**编造引擎未返回的数值（如用哈希值反推排名）

## 16. 外发确认与费用透明（本项目最重要的一个界面）

> PRD §3.5 差异化第 2 条：费用与配额中立，不把空结果包装为成功。
> PRD EARS #7/#8：发送前必须列出目标引擎、帧数、第三方费用/登录要求和「原视频不发送、帧会发送」的说明，并取得明确确认；未确认时外部搜索请求数 = 0。
> PM 结论：市场空白不是更花哨，而是**费用/状态透明与可恢复性**。

**这是全产品唯一一个「阻断式」界面，且阻断是有意的** —— 它是用户与外部引擎之间唯一的知情同意关卡，不能做成可跳过的一次性提示。

### 16.1 触发时机

| 触发 | 说明 |
|---|---|
| 用户点击「开始外部搜索」 | 首次对该任务发起搜索 |
| 任务恢复后有待发送项 | **必须重新确认**（EARS #19：不得在未确认时自动重发外部请求） |
| 用户新增帧后继续搜索 | 仅对新帧部分确认，展示增量 |

## 17. 队列控制、断点恢复与批量操作

### 17.1 队列操作（PRD §5.2 P0-B / P0-C）

| 操作 | 位置 | 行为 | 依据 |
|---|---|---|---|
| **暂停** | 任务行 / 详情页工具条 | 立即停止启动新的外部请求，**已发出的请求允许安全结束并记录结果**；按钮变为「继续」 | EARS #21 |
| **继续** | 同上 | 从暂停处继续；若此前有待确认项，重新走 §16 确认流程 | EARS #19 |
| **仅重试失败项** | 详情页工具条 Primary | 只重跑状态为 `rate_limited / network / parse / credential` 的项，**不重跑 `hit` 与 `zero`** | P0-B |
| **跳过某引擎** | 引擎 chip 上的 `ban` 图标 | **provider 级停用**：该引擎所有未完成项标记为 `skipped`，已完成结果保留。**必须在执行层生效** —— 停用后任何入口（批量队列 / 断点恢复 / 重试 / 定时任务）均不得再向该 provider 发送请求，**不得仅停用界面入口** | PRD §10 合规「各 provider 必须能单独停用」（**执行层约束，见 §20.6**） |
| **跳过某帧** | 帧网格右键 / hover 菜单 | 该帧所有未完成项标记 `skipped` | P0-B |
| **转手工检索指引** | `captcha` 状态项的操作区 | 打开该引擎网页 + 显示本帧缩略图 + 提示「请手动上传此帧，把结果 URL 粘贴回结果列表」；**不提供绕过验证码的自动方式** | PRD 合规红线 |
| **删除任务** | 任务行 `trash` | 二次确认，明确列出将删除：帧图 / 结果 / 导出临时文件 / 日志索引；**完成后报告成功项数与无法删除项明细** | EARS #20 |

### 17.2 断点恢复（EARS #19 / GWT #6）

应用重启后必须恢复：未删除任务、已生成帧、已完成结果、未完成状态。

**恢复后的状态映射（关键）：**

| 关闭时的状态 | 恢复后显示 | 是否自动重发 |
|---|---|---|
| `pending`（已确认过） | `pending` + 徽章「待确认」 | **否** —— 需重新走 §16 |
| `sending` | `pending` + 「上次未完成的请求已取消」 | **否** |
| `hit` / `zero` / `skipped` / `cancelled` | 原样 | 否 |
| `rate_limited` / `network` / `parse` | 原样 + 「可重试」 | 否 |

**恢复提示条**（info 级 DegradedBanner，进入任务时显示一次）：
「已恢复上次的进度：128 项中 47 项完成，81 项待确认。外部请求不会自动重发。」+ Primary「继续并重新确认发送」

### 17.3 批量与并发

- 多视频按任务排队，**单个任务失败不得清空其他任务或已完成结果**（P0-C）

### 关于「跳过某引擎」：判据修正（PM 于 2026-10-23 纠正本人的错误判断）

**我原来的判断是错的，PM 的反驳成立。** 我原以为「跳过某引擎 = 用户显式操作、不做就立即可见、无静默形态」，据此判断不需补 EARS。

**错在哪：** 我误把自己的规范读窄了。§17.1 里我写的就是 **「provider 级停用：该引擎所有未完成项标记为 `skipped`」**——语义是**停用整个 provider**，不是单次跳过一帧。
**一旦语义是 provider 停用，失效形态就变了：** 若只停用界面入口、而其他入口（断点恢复、批量队列、重试）仍向该 provider 发送请求，则失效形态是**静默烧配额**，与 #28 同类。
**我拿"单次跳过"的失效形态，去论证"provider 停用"不需要验收——用错了判据的对象。**

**处理结果（PM 于后续复核推翻了"暂缓"裁定）：**

**已按终判处理**（见 §17.1 与 §20.6 第 9 条，依据栏为 **EARS #30**）。

### 「要不要升格为 EARS」的判据（PM 提炼，本人采纳）

> **无 EARS 编号的风险本质是「验收时被静默跳过」。而是否静默，取决于失效形态，不取决于功能重要性。**

| 失效形态 | 是否需独立 EARS | 例 |
|---|---|---|
| **静默失效**（用户不知情，系统照跑照花钱） | **是** | #28 重试过滤、#24 回环绑定、#25 CSV 注入、**#30 provider 停用执行层** |
| **立即可见**（不做就直接看得出来） | 否，PRD 表格背书即可 | 单次跳过一帧的按钮 |

**#30 的判据演变（完整记录，避免后人误以为是重复条目）：**

| 时点 | 判断 | 依据 |
|---|---|---|
| 初判 | 不需补 | 「跳过某引擎 = 用户显式操作、失效立即可见」——**用错了对象** |
| 复核 | 属静默，但暂缓 | 已识别「provider 停用若只在界面层生效则静默烧配额」，却仍挂起待架构评审 |
| 终判 | **补 #30** | 已识别的静默风险不应挂起——**判据一旦成立就该落地** |

**本条最值得记住的一点：** 同一个功能名，「单次跳过一帧」与「provider 级停用」的判据结论相反。**判据作用于语义，不作用于功能名。**

**我原来的筛法是「无编号 + 实现侧 + 有成本后果」三因子计数——漏了「是否静默」这个决定性因子。** 按因子数筛会把"三个因子都沾一点但不静默"的项误升格，也会把"只沾两个因子但静默"的项漏掉。
**改用单一判据（是否静默）比按因子数更准。**

**已知豁免行（2026-10-23 基线，共 2 类）：**

### 20.5 「界面词 vs 数据词」分歧的默认解法

PM 建议将 §13.1b 的命名分层表确立为后续同类分歧的默认解法。**采纳，并记录为设计原则：**

当出现「界面上怎么叫」与「数据/导出里怎么叫」冲突时，**不二选一，做分层**：

| 层 | 选词标准 | 例子 |
|---|---|---|
| **界面标签** | 选**描述它干什么**的词，优先低技术用户的可理解性 | 排序分 |
| **数据字段名 / 导出列名 / 帮助说明 / PRD** | 选**描述它不是什么**的词，承载产品对外承诺与可追溯性 | 线索分 |

**判断依据：** 界面词面向"这一次操作"，数据词面向"这份证据以后被谁、怎么读"。维权用户会把导出的 CSV 交给第三方，那时候「线索分」的定性含义比「排序分」的功能含义重要得多。

**同时必须做两件事，缺一不可：**
1. 在文档中显式列出分层表（如 §13.1b），说明两者同义
2. 在导出说明里显式标注界面与导出的命名差异

**PM 补充的塌缩条件（记录以备将来）：** 若将来出现"导出只给自己看"的场景，这层分层可以塌缩成一个词。目前不存在该场景，维持分层。
