reverse-video-search

本地运行的反向视频溯源：抽帧 → 多引擎以图搜图 → 去重排序 → 导出。数据留在本机，外发需逐任务显式授权。

这是一个项目说明页。本工具依赖 Node.js 与 ffmpeg，必须在你的本机运行——GitHub Pages 只能托管静态页面，无法承载这个服务。

要真正使用，请克隆仓库后按下方「快速开始」在本机启动。

它能做什么

  • 抽帧：固定间隔 / 场景切换 / 两者合并，可设上限与阈值；检测不到场景切换时自动回退固定间隔。
  • 去重：感知哈希在本机计算，相同帧自动分组，不重复检索。
  • 检索：Bing / Yandex / Google Lens 三家，逐引擎并发排队，带熔断与最小间隔。
  • 结果：双轨分数（引擎名次 + 本地哈希实算），标注分数来源，不做伪精确。
  • 降级：四级链路，每一级跳过都写进降级日志，可回溯，不静默失败。
  • 导出：CSV（防公式注入）/ JSON / 帧图包。

引擎能力（如实标注）

引擎当前实际说明
Bing 图片 可自动 深链已验证、图床桥接已验证。勾选桥接并选站点后自动跑通。
Yandex 图片 会尝试 未验证，结果不保证。
Google Lens 只能手动 结果页是纯 JS 应用外壳，HTTP 层拿不到数据。上传端点本身是通的（303 跳转到真实结果页），但内容靠浏览器渲染。

Lens 这一路的手动成本已尽量压低：任务详情页打开「手动跑腿工作台」，按帧聚合，点「复制帧图片」后到 Lens 上传页按 Ctrl+V，或直接把缩略图拖到上传区。

环境要求

  • Node.js ≥ 22.5.0（用到内置 node:sqlite）
  • ffmpeg / ffprobe（抽帧与预检的硬依赖）
  • 零 npm 运行时依赖，不需要 npm install

快速开始

# 1. 确认 ffmpeg 可用
ffmpeg -version && ffprobe -version

# 2. 启动（默认 http://127.0.0.1:4173）
npm start

只绑定回环地址（127.0.0.1），不对外暴露。没有账号体系，单机自用。

已知边界

  • 引擎可达性依赖对方网页结构，任何一家改版都可能让自动链路失效——失效时降级为手动并在降级日志写明原因。
  • 本项目是独立实现，不抓取、不镜像原站的付费内容与私有资源。
