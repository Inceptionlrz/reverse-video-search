# Reverse Video Search 本地独立版 PRD

- 文档版本：v1.0
- 调研日期：2026-10-23
- 产品形态：本地单机工具，不是 SaaS
- 参考边界：仅参考 reverse-video-search.com/zh-cn 的用户流程与信息结构，页面、接口与代码均独立实现
- 合规红线：不抓取、不镜像、不缓存原站付费内容或私有资源；仅缓存本应用自行抽取的帧图与自行获得的公开搜索结果

## 1. 产品定义

### 1.1 一句话描述

一款中文本地单机工具：在设备内从本地视频抽取代表性帧，在用户知情选择后将帧提交至可用的公开反向图片搜索引擎，并把来源页面、标题、缩略图和匹配线索透明地汇总、去重、排序与导出。

### 1.2 问题陈述

版权维权者、内容溯源记者和二创素材核查者需要从一段本地视频追查公开网络上的可能来源。现有做法集中暴露出以下问题：

1. **按次收费但不保证命中**：参考站条款明确“搜索执行即消耗积分”，零结果也属于已完成服务，通常不退款；用户付费购买的是一次尝试，而不是可验证的结果。
2. **手工流程重复且不可复盘**：用户需自行截图、逐帧切换 Google Lens、Bing、Yandex、TinEye，再复制链接到表格，批量任务成本高且容易漏帧、重复记录。
3. **第三方不稳定被包装成产品失败**：外部引擎会限频、要求验证码、调整页面结构、返回空结果或停止 API；现有工具常缺少逐帧、逐引擎状态和可恢复操作。
4. **隐私与能力边界不透明**：原视频可以本地抽帧，但搜索帧仍会发送到第三方。参考站条款还写明帧可能被置于公开、无需鉴权的 URL 供搜索引擎拉取。用户需要在发送前知道“什么数据将发往哪里”。
5. **“最可能来源”不等于“原始来源”**：搜索引擎只覆盖已索引的公开网页，不能看到私密、已删除、登录墙或未索引内容；高排名只能作为调查线索，不能自动成为版权、新闻或司法结论。

### 1.3 产品目标

- 将“抽帧—多引擎检索—汇总—去重—导出”收敛为一个可复盘的本地工作流。
- 原始视频始终留在本机；任何帧对外发送前明确告知目标引擎并取得用户确认。
- 不向用户收取本应用积分或订阅费；若用户选择需要密钥或计费的第三方接口，费用、配额和凭据均由用户自行管理。
- 外部接口失败时保留已完成工作，展示真实原因并支持安全重试、跳过或转人工处理。

### 1.4 非目标

本产品不是互联网自建图片索引、不是人脸识别工具、不是深伪检测器、不是事实核查结论生成器，也不承诺找到视频的真正首发者。

## 2. 目标用户

### 2.1 主要画像 A：版权维权者 / 独立创作者

- 年龄与职业：22–45 岁；摄影师、短视频创作者、MCN 版权运营、独立制片人
- 场景：收到盗用线索后，用原片或下载片段查找转载页面并整理链接
- 技术水平：中等，能安装桌面工具，但不希望维护脚本
- 核心诉求：批量处理、跨引擎覆盖、保留帧与来源关系、可导出证据线索
- 当前替代：逐帧截图 + 多网站手工上传 + Excel

### 2.2 主要画像 B：内容溯源记者 / OSINT 调查者

- 年龄与职业：25–50 岁；记者、事实核查编辑、研究人员、公益调查者
- 场景：核查热点视频是否为旧视频重发，寻找更早出现的公开页面
- 技术水平：中高，理解搜索结果需要二次核验
- 核心诉求：时间戳可追踪、多引擎交叉证据、零结果不被伪装、失败状态可解释
- 当前替代：InVID 类工具抽帧后逐个引擎检索，手工写调查日志

### 2.3 次要画像 C：二创素材核查者 / 内容编辑

- 年龄与职业：18–40 岁；视频编辑、社媒运营、自媒体作者
- 场景：投稿前确认素材出处、寻找高清或未裁剪版本、补充来源署名
- 技术水平：低至中等
- 核心诉求：中文界面、默认参数可用、结果聚合清晰、CSV/JSON 可交给后续流程
- 当前替代：只搜一张截图，命中差时不知道下一步怎么办

## 3. 调研基线与竞品分析

### 3.1 行业知识库基线

专家包中没有“媒体检索”专用文件。本项目最接近“内容 / 社区平台”，因此采用 `references/industries/content-platform.md` 作为有限基线：结果卡片需具备封面、标题、摘要/来源和状态，图片需懒加载，必须设计空状态，强调色每屏不超过两处。该文件主要提供内容展示与交互基线，不提供反向搜索定价或引擎覆盖数据；后者以联网调研补充。

### 3.4 差评与市场空白结论

1. **收费抱怨的本质不是“任何外部服务都应免费”**，而是费用、查询次数、失败原因和结果价值不对称。参考站合同口径把“查询已执行”与“是否命中”分离；其当前自动退回零命中积分的做法又不是合同承诺，可被未来撤回。市场空白是把每次尝试的去向、状态、配额、退回规则和产出透明展示，并允许用户选择免费手工桥接或自备商业 API。
2. **用户要的是可复盘工作流，不只是上传按钮**。单引擎会漏检；多引擎手工重复；真正价值在于帧—引擎—结果之间的完整关联、去重、排序和导出。
3. **空结果需要可行动解释**。应区分“引擎正常返回零命中”“限频”“验证码”“网络超时”“凭据无效”“解析字段缺失”，而不是统一显示“搜索失败”。
4. **准确率必须诚实表达**。相似度只能是引擎分数或本地聚合启发式，不能表示“这是原作者”的概率；同一 URL 被多个帧/引擎命中可提升线索优先级，但仍需人工核验。
5. **本地隐私只是相对优势**。原视频不离机，但被搜索的帧会发送给第三方；敏感内容必须让用户逐任务选择引擎并确认。
6. **供应商变动是常态**。Bing 旧 API 退休说明产品不能把某一家当作永久必达依赖，必须有 provider 级可用性和降级模型。

### 3.5 我们的差异化

- **本机优先**：原视频、抽帧、任务数据和应用缓存留在设备；仅在明确开始搜索后发送所选帧。
- **费用与配额中立**：本应用不设积分墙；任何第三方计费、配额与错误原样标识，不把空结果包装为成功，也不承诺外部服务免费无限。
- **逐帧可审计**：每个帧 × 引擎都有状态、时间、重试次数、返回条数和错误类型。
- **失败可恢复**：一个引擎不可用不阻断其他引擎；支持暂停、继续、仅重试失败项和转手工检索。
- **线索而非结论**：来源页、帧时间戳、引擎和匹配依据一并导出，明确要求人工验证。

## 4. 核心流程

1. 用户新建本地任务并选择一个或多个本地视频。
2. 系统完成格式、时长、磁盘空间与可解码性预检，展示视频元数据。
3. 用户选择固定间隔或场景变化抽帧方式，并配置目标帧数上限。
4. 系统在本机抽帧，展示时间戳、缩略图和抽帧进度；用户可取消或移除低价值帧。
5. 用户选择搜索引擎；系统明确列出哪些帧将发送给哪些第三方，并取得确认。
6. 系统按受控并发执行检索，逐帧、逐引擎展示状态；遇限频、验证码或不可用时降级但不丢失已完成结果。
7. 系统标准化来源页面、标题、缩略图、引擎、帧时间戳和匹配依据，并进行 URL 去重和可解释排序。
8. 用户核验来源页面，按任务/视频/帧/引擎筛选，并导出 CSV 或 JSON。
9. 用户可删除任务，清理本应用生成的帧图、结果和运行日志。

`RICE = Reach × Impact × Confidence / Effort`。Reach 取 1–10；Impact 取 0.25/0.5/1/2/3；Confidence 取 0.5/0.8/1；Effort 取 1–10。评分按产品能力包而非技术子任务计算，以保证 MVP 仅有 3 个核心功能。RICE 相同或接近时，以用户已锁定的端到端主流程依赖和合规风险作为决胜条件，因此多引擎能力优先于可独立后置的单图入口。

### 5.2 P0 功能清单

#### P0-A 本地视频预检与可配置抽帧

- 支持选择一个或多个本地 MP4、MOV、WEBM 文件。
- 创建任务前检查格式、可解码性、时长和可用磁盘空间；失败时给出具体文件名与原因。
- 抽帧模式：固定间隔、场景变化；均可设置帧数上限。
- 每帧显示缩略图、序号和 `HH:MM:SS.mmm` 时间戳；允许删除不参与搜索的帧。
- 原始视频不得上传或复制到第三方；仅允许缓存本应用生成的帧。

#### P0-B 多引擎搜索与透明降级

- 引擎选择至少覆盖 Google Lens、Bing Visual Search、Yandex Images；只有在合法、可用且符合条款的接入路径存在时才显示“可自动检索”。
- 发送前明确展示目标引擎、帧数量、是否需要登录/密钥、是否可能产生第三方费用。
- 每个“帧 × 引擎”显示：待处理、发送中、成功有结果、成功零结果、限频、需验证码、凭据错误、网络错误、解析异常、已跳过、已取消。
- 支持暂停队列、继续、仅重试失败项、跳过某引擎、转到手工上传指引。
- “仅重试失败项必须在执行层过滤 `成功有结果` 与 `成功零结果` 两类状态”，不得只是隐藏入口；任何入口触发的批量重试都不得重跑这两类，避免重复消耗外部配额。
- 处于需验证码状态的项目只能提供合规的手工检索指引，不得提供自动重试能力。
- 不得绕过验证码、登录、付费墙、地理限制、机器人防护或服务条款。

#### P0-C 批量任务与结果包

- 多视频按任务排队；单个任务失败不得清空其他任务或已完成结果。
- 结果最小字段：任务、视频文件名、帧序号、帧时间戳、搜索引擎、来源页面 URL、页面标题、缩略图 URL/本地缓存状态、引擎原始分数（如有）、归一化相似度/排序分（线索分，如有）、首次检索时间、状态。
- URL 去重需忽略常见追踪参数；合并项保留所有命中帧、引擎和命中次数，不得因去重丢失证据关系。
- 默认按可解释线索分降序；同分时按“跨引擎命中数—跨帧命中数—首次出现顺序”稳定排序。
- 相似度必须标识来源：`引擎提供`、`本地归一化` 或 `无分数`，不得展示伪精确百分比。
- 排序/分数列禁止使用暗示概率或结论的措辞（`匹配度`、`置信度`、`准确率`、`命中概率` 等）。数据字段名沿用“线索分”，面向 C 类低技术用户的界面标签优先写“排序分”，帮助说明中保留“线索分”表述并标注“不代表来源真实性概率”。
- CSV/JSON 导出必须遵循当前筛选范围，并保留原始 URL、中文、换行和引号的正确转义。
- 导出文件的数据列名沿用产品概念名（如 `线索分`、`分数来源`），不得把界面标签直接当作表头；界面与导出的差异需在导出说明中显式标注，避免下游误读。

### 5.3 MVP 范围

MVP 仅包含上述 3 个 P0 能力包：

1. 本地视频预检与可配置抽帧。
2. 多引擎搜索与透明降级。
3. 批量任务与结果聚合、去重、排序、CSV/JSON 导出。

P1/P2 全部进入 Backlog，不得因“顺手实现”进入首版。

## 6. 明确不做（Out-of-Scope）

| 不做项 | 原因 |
|---|---|
| 抓取、镜像、转发或缓存参考站的付费搜索结果、账户数据、令牌与私有资源 | 侵犯服务边界与用户明确红线；本项目必须独立产生结果 |
| 绕过第三方登录、验证码、付费墙、限频、地域限制或反机器人机制 | 合规与账户封禁风险；“可用”不能建立在规避控制之上 |
| 自建全网图片/视频爬虫与互联网索引 | 成本、版权、隐私与运维范围远超本地 MVP |
| 人脸识别、人物身份识别或陌生人搜索 | 高隐私与滥用风险，也不是视频来源追踪的必要能力 |
| 访问私密、已删除、仅好友、登录墙或未被搜索引擎索引的内容 | 技术与授权边界不可控，不能承诺覆盖 |
| 深伪检测、事实核查结论、侵权裁定或司法取证结论 | 搜索结果只是线索，需要人工与其他证据交叉验证 |
| 自动发送 DMCA/律师函、平台投诉或下架请求 | 涉及法律判断、主体资格和误伤风险；首版只导出线索 |
| 云端账号、订阅计费、多租户、团队协作、云同步 | 产品明确为本地单机工具，避免引入无关复杂度与隐私风险 |
| 从 TikTok/YouTube/Instagram 等 URL 自动下载视频 | 用户需求已锁定为本地视频上传，且下载涉及平台条款与版权风险 |
| 移动端与微信内运行 | 抽帧、批量任务和浏览器桥接在移动端约束大；首版聚焦桌面 |
| 永久缓存第三方缩略图或源页面全文 | 版权、隐私和陈旧数据风险；可显示远程缩略图或明确的短期应用缓存状态 |
| 保证找到“唯一原始来源”或保证召回率/准确率 | 第三方索引非穷尽且首发时间、转载链与删除状态不可可靠推断 |

## 7. EARS 格式验收标准

> 句式约定：`While/When/If + 条件，系统 + 必须 + 可观察行为`。

### 7.1 本地导入与抽帧

1. **When** 用户选择可解码的 MP4、MOV 或 WEBM 本地文件，**系统必须**创建待抽帧任务并展示文件名、时长、分辨率和本地路径脱敏标识，且不得向任何外部地址发送原始视频。
2. **If** 文件格式不支持、文件损坏或无法解码，**系统必须**阻止该文件进入搜索队列，并展示可操作的具体原因，不得只显示“未知错误”。
3. **If** 可用磁盘空间不足以生成预计帧缓存，**系统必须**在抽帧前停止任务、显示预计需求与当前可用空间，并保留其他任务。
4. **While** 系统正在抽帧，**系统必须**展示当前视频、已完成帧数、目标/上限帧数和可取消操作；取消后必须保留取消前已生成帧供用户选择清理或继续。
5. **When** 用户选择固定间隔模式并设置帧数上限，**系统必须**在不超过上限的前提下按整个视频时长均匀取样，并为每帧记录毫秒级时间戳。
6. **When** 用户选择场景变化模式，**系统必须**抽取满足场景变化条件的代表帧；**If** 未检测到足够场景变化，**系统必须**明确提示并允许回退到固定间隔，不得静默返回空任务。

### 7.2 外部搜索与降级

7. **When** 用户首次启动某任务的外部搜索，**系统必须**在发送前列出目标引擎、待发送帧数、可能的第三方费用/登录要求和“原视频不发送、帧会发送”的说明，并取得明确确认。
8. **If** 用户未确认外部发送，**系统必须**保持全部帧在本地且不得发起任何搜索引擎网络请求。
9. **While** 搜索队列运行，**系统必须**为每个帧与引擎组合展示唯一状态，并持续保留已成功结果，不得因后续单项失败回滚成功项。
10. **If** 外部引擎返回限频、超时、验证码、凭据错误或服务不可用，**系统必须**映射为不同错误类型，展示建议动作和可重试时间（若可获得），不得无限自动重试。
11. **If** 一个引擎不可用而至少一个其他引擎可用，**系统必须**继续执行可用引擎，并把任务标记为“部分完成”而非“全部失败”。
12. **If** 所有已选引擎都不可用，**系统必须**暂停未发送项、保留帧和历史结果，并提供“稍后继续”“更换引擎”“手工检索指引”三类可行动选项。
13. **When** 引擎正常响应但返回零命中，**系统必须**将该项标记为“成功零结果”，不得标记为网络错误，也不得伪造命中数量或候选链接。
14. **If** 自动接入路径会违反目标引擎条款或需要绕过验证码/登录/付费控制，**系统必须**禁用自动方式并降级为合规的手工流程说明。

### 7.3 聚合、排序与导出

15. **When** 外部引擎返回候选项，**系统必须**为每项保存来源引擎、对应帧和时间戳、来源 URL、标题、缩略图引用及分数来源；缺失字段必须显示为空或“未提供”，不得臆造。
16. **When** 多个结果仅追踪参数不同但指向同一规范 URL，**系统必须**合并为一条结果，同时保留全部命中帧、引擎与命中次数。
17. **When** 用户按相似度排序，**系统必须**优先使用可比较的明确分数，并标注分数是引擎提供还是本地归一化；无分数项必须单独标识且排序稳定。
17b. **When** 界面展示任何排序或分数列，**系统必须**使用“排序分/线索分”等非概率措辞，并在同屏可见位置提示其不代表来源真实性概率且需人工核验；不得使用匹配度、置信度、准确率等措辞。
18. **When** 用户选择 CSV 或 JSON 导出，**系统必须**导出当前筛选范围内的所有可见结果与帧/引擎证据关系，且文件能被标准解析器重新读取。
19. **When** 用户暂停并重新打开应用，**系统必须**从本地恢复未删除任务、已生成帧、已完成结果和未完成状态；不得自动重发外部请求。
20. **When** 用户删除任务并确认清理，**系统必须**删除该任务由本应用生成的帧、结果、导出临时文件和日志索引，并报告成功项与无法删除项。
21. **While** 多视频批量任务正在执行，**系统必须**限制并发以尊重引擎配额；用户暂停队列后，系统不得启动新的外部请求，但允许已发出的请求安全结束并记录结果。
22. **If** 来源链接打开后跳转、失效或与结果标题不一致，**系统必须**允许用户标记“待核验/排除”，且不得自动把该链接认定为原始来源。

### 7.4 安全、隐私、配额与离线（实现侧，设计文本扫描无法验证）

> 编号规则：本节与全文档共用一套 EARS 编号，编号一经分配不再重排；新增条目追加在末尾，历史引用保持有效。跨文档协作时请按编号引用，不要按行号或条目位置引用。

23. **When** 应用首次启动且用户未主动开启遥测，**系统必须**保持遥测为关闭状态，且不得把开启选项设为默认勾选；关闭状态下不得产生任何外发遥测请求。
24. **While** 应用运行任何本地服务或监听端口，**系统必须**仅绑定回环地址，不得监听局域网或公网接口，并在启动自检失败时阻止启动或降级为无需监听的模式。
25. **When** 导出 CSV 且字段值以 `=`、`+`、`-`、`@`、制表符或回车开头，**系统必须**对该值做防公式注入处理，使表格软件将其作为文本读取而非可执行公式。
26. **If** 设备处于离线状态，**系统必须**仍允许完成本地视频预检与抽帧，并把需要网络的步骤明确标为“等待联网”，不得因离线禁止本地阶段。
27. **When** 界面出现空状态，**系统必须**对“无任务”“抽帧 0 帧”“搜索 0 命中”“筛选后 0 条”分别给出不同文案与下一步操作，不得复用同一空状态文案。
28. **When** 用户在任一入口（含批量操作与断点恢复后）触发“仅重试失败项”，**系统必须**只重跑状态为限频、网络错误、解析异常、凭据错误的项，不得重跑“成功有结果”与“成功零结果”；该过滤必须在执行层生效，不得仅隐藏入口。
29. **While** 系统写入任何本地日志、诊断文件或导出文件，**系统必须**排除第三方 API 密钥与凭据；**If** 日志或导出需要引用凭据，则只写入脱敏标识。
30. **While** 某个 provider 处于停用状态，**系统必须**在执行层阻止向该 provider 发送任何请求——批量队列、断点恢复、重试与定时任务各入口均不得例外，不得仅停用界面入口；**When** 用户停用 provider，**系统必须**把该 provider 所有未完成项标记为已跳过。

> #30 收录说明：本条曾被裁定「暂不新开 EARS」，依据当时「跳过某引擎属用户显式操作、失效立即可见」的判断。后经复核确认该判断用错了对象——「单次跳过一帧」可见，但「provider 级停用」若只在界面层生效，后台仍持续发送，失效形态为静默消耗外部配额，与 #28 同类。按「是否静默失效」这一判据，本条应独立收录，故 #30 予以补入。

## 8. Given / When / Then 核心场景

1. **Given** 用户已选择 3 个有效本地视频且未授权外发，**When** 用户执行场景变化抽帧，**Then** 系统仅在本地生成带时间戳的帧并保持网络搜索请求为 0。
2. **Given** 某任务已生成 20 帧，**When** 用户只选择其中 5 帧并确认发送至两个引擎，**Then** 系统最多创建 10 个帧 × 引擎检索项，其他 15 帧不外发。
3. **Given** Google 路径限频而 Yandex 正常，**When** 批量搜索执行，**Then** Google 项显示限频并等待用户决定，Yandex 项继续，任务最终显示部分完成。
4. **Given** 两个引擎对三个帧返回同一来源 URL 且仅追踪参数不同，**When** 系统聚合结果，**Then** 页面只显示一条规范结果并列出 3 个帧与 2 个引擎证据。
5. **Given** 当前筛选条件仅显示相似度不低于阈值的结果，**When** 用户导出 CSV，**Then** CSV 仅包含当前结果集，并正确转义中文、逗号、引号和换行。
6. **Given** 应用在任务执行中被关闭，**When** 用户再次启动，**Then** 已完成结果和待处理状态从本地恢复，且系统不在未经确认时自动重发外部请求。
7. **Given** 外部引擎正常返回空列表，**When** 系统记录响应，**Then** 项目状态为成功零结果并提供更换帧/引擎建议，而不是显示成功命中或通用失败。
8. **Given** 用户确认删除任务，**When** 清理完成，**Then** 任务列表不再显示该任务，本应用生成的帧与结果文件不可从应用缓存目录访问，失败删除项有明细。

## 9. 边界条件与状态设计

| 类别 | 必须覆盖的情形 | 产品行为 |
|---|---|---|
| 空状态 | 无任务、抽帧 0 帧、搜索 0 命中、筛选后 0 条 | 分别解释原因与下一步；不得用同一空文案 |
| 错误状态 | 文件损坏、磁盘不足、网络断开、DNS、429、401/403、验证码、第三方结构变化、缩略图失效 | 分类显示；保留已完成结果；提供对应操作 |
| 加载状态 | 预检、抽帧、排队、发送、等待、解析、导出 | 显示当前阶段与可取消范围，避免无限转圈 |
| 边界值 | 0 秒/仅音频文件、超长视频、超大分辨率、可变帧率、旋转元数据、无明显场景变化、同名文件 | 预检明确处理或拒绝；时间戳与任务 ID 不冲突 |
| 并发 | 多视频、多帧、多引擎同时排队 | 有受控并发与公平队列；暂停后不再启动新请求 |
| 离线 | 抽帧时离线、搜索中断网、恢复网络 | 本地抽帧可继续；外部项暂停并可继续，不丢本地数据 |
| 权限拒绝 | 文件读取、缓存目录写入、浏览器扩展权限被拒 | 明确权限用途与恢复路径；拒绝后仍可清理已创建数据 |
| 数据缺失 | 无标题、无缩略图、无相似度、URL 失效 | 保留结果并标“未提供”，不得补造 |
| 安全内容 | 恶意文件、超长文件名、CSV 公式注入、危险 URL 协议 | 校验输入；导出时防公式执行；只允许安全协议打开 |
| 第三方变化 | 引擎 UI/API 停服或字段改变 | provider 级熔断/不可用状态；其他引擎继续；不伪造结果 |

## 11. 数据埋点与验证方案

### 11.1 原则

这是本地单机工具，不存在注册、订阅或支付漏斗。MVP 默认只写入本地匿名事件日志，用于用户自行诊断和在授权时导出；不默认上传分析平台。`sign_up_complete`、`upgrade_click`、`payment_complete` 明确不适用，禁止为了指标而虚设账号或付费功能。

### 11.2 必埋事件

| 事件类别 | 事件名 | 说明 / 关键属性 |
|---|---|---|
| 获客/启动 | `app_opened` | 应用版本、OS、启动耗时；不记录 IP |
| 激活 | `task_created` | 首个本地任务创建；格式、时长区间、文件数量，不记录文件名/路径 |
| 核心激活 | `frame_extraction_completed` | 模式、耗时、帧数、是否回退、失败类型 |
| 外部发送 | `search_consent_confirmed` | 引擎列表、帧数；不记录图像或查询内容 |
| 搜索 | `provider_search_completed` | provider、状态、耗时、结果数区间、重试次数 |
| 降级 | `provider_rate_limited` / `manual_fallback_opened` | provider、错误类别、用户采取的动作 |
| 聚合 | `results_deduplicated` | 原始条数、去重后条数、跨帧/跨引擎命中计数区间 |
| 转化 | `results_exported` | CSV/JSON、结果条数、筛选是否启用 |
| 留存 | `session_started` / `session_ended` | 本地匿名 session_id、时长；不上报云端 |
| 异常 | `error_occurred` | 模块、错误码、是否恢复；不得含原始输入与密钥 |
| 清理 | `task_deleted` / `cache_cleared` | 删除项数量、失败项数量、释放空间区间 |

### 11.3 属性与实现要求

- 事件命名使用 `{对象}_{动作}`，属性至少包括 `anonymous_install_id`、`timestamp`、`device_os`、`app_version`；不使用云端 `user_id`。
- 不采集 IP、视频/帧内容、原始文件名、完整路径、搜索密钥、来源页正文或用户备注。
- 统计目标：首次任务创建率、抽帧完成率、至少一个 provider 成功率、零结果率、限频率、失败恢复率、结果导出率。
- 产品假设验证：若“抽帧完成但未启动搜索”占比高，优先检查隐私告知或接入门槛；若“搜索完成但未导出”高，优先检查结果质量和去重/排序可解释性。

## 12. 成功指标与发布门槛

### 12.1 MVP 成功指标（内部测试/授权遥测）

- 有效视频抽帧完成率 ≥ 95%。
- 外部引擎发生单项失败时，已完成结果保留率 = 100%。
- 限频/验证码/凭据/网络/零结果五类状态识别正确率 = 100%（基于测试夹具）。
- 相同规范 URL 的去重准确率 ≥ 99%，且证据关系丢失率 = 0。
- CSV 与 JSON 导出由标准解析器回读成功率 = 100%。
- 未确认外发时外部搜索请求数 = 0；原始视频对外上传请求数 = 0。

### 12.2 发布阻断条件

出现任一情况不得发布：

- 调用了参考站私有/付费接口或缓存其付费结果。
- 原始视频或未选择的帧被外发。
- 把空结果展示为命中、伪造相似度或隐藏 provider 错误。
- 自动绕过验证码、限频、登录或付费控制。
- 删除任务后仍可从应用界面恢复其帧或结果，且未明确提示残留。
- 导出包含第三方密钥、完整本地路径或未经转义的可执行表格公式。

## 13. 风险与待验证项

| 风险 | 影响 | 产品缓解 |
|---|---|---|
| Google/Yandex/Bing 消费页面或条款变化 | 自动检索可能失效 | provider 独立开关、可用性状态、手工降级，不承诺永久自动化 |
| Bing 旧视觉 API 已退休 | 结构化结果接入受限 | 不把旧 API 作为验收前提；以架构评审后的合规路径为准 |
| 外部引擎配额或商业 API 成本 | 用户误以为“本地版=所有搜索永久免费” | 发送前显示费用归属和配额；本应用不设积分，但不替第三方买单 |
| 相似度不可横向比较 | 错误排序导致误判原始来源 | 标注分数来源；无可比数据时采用可解释线索分并允许按引擎筛选 |
| 敏感帧发往第三方 | 隐私泄露 | 原视频本地、逐任务确认、按帧取消、第三方说明、可清理本地缓存 |
| 视频经过裁剪/镜像/水印/重编码 | 召回率下降 | 多帧、多引擎；高级帧处理放入 P2，不夸大首版能力 |

待架构评审确认：每个 provider 的合法接入方式、是否需要浏览器扩展/用户自备 API、凭据存储、并发上限与缓存保留策略。PRD 只约束用户可观察结果，不预设具体技术库。
